# Step2 显示与主要经营指标请求修复

## 已确认原因

用户提供的日志包含两种 Arrow 序列化失败：数值列混有“详见下表”，实际值列混有文字和浮点数。Streamlit 会尝试自动修复，所以这类日志本身不能证明模型提取失败。截图中的阻断另有来源：OPERATING_METRICS:REQUEST_COVERAGE（请求未完成）和 INSURANCE_REVENUE:REQUIRED（必需指标未取得）。附件没有记录模型请求的具体异常，不将 Arrow 报错当作接口超时证据。

## 修复边界

- 新增展示副本转换：仅把 Arrow 不兼容的混合类型列转换为文本，空值显示空白，纯数值列保持数值类型。原 DataFrame、计算、Excel 导出不修改。
- 接入 Step2 预览、校验明细、盲测明细及 Step3/Step5 窄表预览。
- 主要经营指标使用精简稀疏输出，数值指标最多8项一批，文本指标单独一批，共用已渲染页面缓存。保持本季度列选择要求、90秒请求超时和受控重试设置。
- 成功批次保留，连接异常、超时、无效响应只重试失败指标。持续失败仍由前置门槛阻断，不假装已确认未披露，不放宽校验。

## 验证

测试复现原始混合类型报错，验证直接 Arrow 序列化、真实页面显示调用无需 Streamlit 自动类型修复、原数值及 Excel 数字单元格不受影响。经营指标测试覆盖29项拆分、文本隔离、单批瞬时/永久失败和局部重试。接口采用受控响应，不代表在线服务或真实模型提取已复测成功。
