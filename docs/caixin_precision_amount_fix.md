# 财信人寿：披露精度与中文注册资本修复

## 原文核验

来源：财信人寿2026Q1偿付能力季度报告摘要，物理页码（非印刷页码）。

- 第 2 页：注册资本为“伍拾亿元整”，即 50 亿元 / 500,000 万元。
- 第 16 页（及第 29 页重复摘要）：汇总金额为万元、两位小数。
- 第 34、35、37、38 页：S02/S03/S05 明细金额为元、两位小数。
- 例如认可资产 59,999,455,957.35 元 = 5,999,945.595735 万元，按汇总表精度四舍五入为 5,999,945.60 万元。相差 42.65 元，不应被固定 1 元容差拦截。

## 规则

1. 保留原有 1 元绝对精度容差；数量、比例的容差不变。不存在按余额百分比放宽。
2. 超过基础容差时，只对人民币金额读取原始值及原单位的显式小数位，核验它与标准数值一致，再把更精细的来源按较粗来源的精度四舍五入。
3. 每一对来源都必须通过；一个低精度摘要不能掩盖两个高精度明细之间的真实冲突。
4. 原文缺失、原单位与标准值不吻合、标准单位不一致、同精度金额超过基础容差，均不放行。为防模型丢失尾随零，仅对明确含至少两位小数的原始金额启用精度对齐；整数或单小数来源保守使用原基础容差。
5. 不改写原始值或标准值，仅更新校验结论并记录原因。
6. 支持完整中文金额表达式（简繁体大写、万/亿、元/圆/整/正、角/分），先确定性解析成元，再换算目标单位。原文自带“亿”时不再重复乘模型返回的单位。
7. 不猜测近似金额、范围、多金额说明、混合格式或歧义简写。不适用、未披露和横杠政策不变，-0.01 元仍是负数，不能变成 0。

## 旧结果兼容

现有 Step2 会话和上传的完整 VLM v2 工作簿复用同一重新校验入口：重新判断跨表精度冲突；仅修复有合法中文原文、found 状态、金额目标单位且尚无标准数值的记录，并更新对应 NUMBER 校验。不清除请求覆盖、期间、证据或其他业务校验失败。新解析的金额如与另一来源冲突，新增跨表失败检查。

没有重新调用模型；原始工作簿不被覆盖。导出和 Step3 适配器接收同一修复后的记录。
