# 民生人寿 S02 请求失败修复（2026-09-18）

## 已核实的原因和边界

截图包含 ACTUAL_CAPITAL:REQUEST_COVERAGE 失败，同时五个必需资本项为 not_disclosed，属于提取请求未完成引起的缺失，不能据此认定报告未披露。缺少该次接口日志，无法确定是读超时、HTTP 错误还是响应格式异常。

原 PDF 物理第 29 页（印刷页码 26）的 S02 为单页表，单位万元，期末数明确披露：

| 指标 | 期末数（万元） |
| --- | ---: |
| 核心一级资本 | 1,440,973.21 |
| 核心二级资本 | 0.00 |
| 附属一级资本 | 416,113.85 |
| 附属二级资本 | 0.00 |
| 实际资本合计 | 1,857,087.05 |

旧代码仍把 S02 全部 30 个目标放在同一请求中，失败影响整表；最低资本和经营指标已有指标分批机制，但实际资本未覆盖。该设计增加单次请求的映射负担与失败影响范围，不代表已证明接口超时的唯一原因。

## 修改

- 五个必需资本合计目标优先单批提取，其他明细每批最多 10 项；小目标表不强行补齐全部 30 项。
- 每批仅返回本批目标；保留期末列、原始单位、原始值和证据。0.00、横杠仍是 disclosed_zero，不省略为未披露。
- 复用同一页面缓存，不重复 PDF 渲染、不增加并发、不延长 90 秒单次请求限制。
- 超时、HTTP 错误、无效 metrics 列表均隔离到失败批次。成功批次及同批成功页面保留；仅失败目标进入受控重试。
- 永久失败继续阻断请求覆盖门槛，不能因为五个合计项成功就把失败的可选明细判为真实未披露。
- 没有硬编码民生金额、放宽业务校验或改写旧提取结果。

## 验证

新增测试覆盖 30 目标分批、原 PDF 图片输入、核心批失败恢复、明细批失败恢复、永久失败阻断、成功结果保留、图片缓存、零值与真实未披露区分。接口响应采用模拟数据，尚未进行在线模型盲测。

应用刷新或重启后，确认 STEP1 实际资本选中物理第 29 页，再重新执行 STEP2。不要将第 30 页的认可资产表当作 S02。
